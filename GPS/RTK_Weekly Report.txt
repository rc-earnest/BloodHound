Thursday 4/23/26

- discovered that the UART data has several types of configurations
- SBP is specific to the Swift software
- NMEA is ASCII-based, with a low data rate, but has a fixed field size, handshake, and end message indicator
- RTCM is an open standard for GNSS observations, which is great for RTK
- I am leaning more towards NMEA transmission over SBP and RTCM, due to the lower data packets and fixed transmission size
- RTCM isn't displaying on my scope, so I think NMEA is the way to go
- NMEA transmissions are less than or equal to 82 characters
- Firmware on the Piksi seemed to be out of date, so I downloaded the correct files and updated the console and Piksi Firmware
- After the download, the console gave me more control over the UART functions.
- It removed the RTCM function, but gave me control over what NMEA data the Piksi sends
- according to the console, NMEA can send out 4 types of data:
	GPGSY NMEA: number of satellites seen, and each satellite's ID number, elevation in degrees, azimuth in degrees, and signal-to-noise ratio 
	GPRMC NMEA: navigation info like time, status, latitude, n/s for latitude, longitude, e/w for longitude, speed in knots, track angle, date, and magnetic variation
	GPVTG NMEA: course over ground in degrees true north, course over ground in degrees magnetic north, speed over ground in knots, speed over ground in km/hr., and mode
	GPGLL NMEA: geographic data like latitude, n/s indicator, longitude, e/w indicator, UTC, and status
- apparently, the NMEA needs to have a baud rate of either 4800 or 9600

- Set up a temporary base station with a tripod, satellite antenna, a preprogrammed Piksi, and a radio
- The base station Piksi was programmed as follows:
	Broadcast = true
	surveyed Lat = Pocatello Latitude, in degrees
	surveyed Lon = Pocatello Latitude, in degrees
	surveyed Alt = Pocatello Altitude, in meters
	UARTA Mode = SBP
	SBP Message Mask = 64
	Configure Telemetry Radio On Boot = true
	Baud Rate = 57600, with 915 MHz radio
- The Rover Piksi was programmed as follows:
	Broadcast = false
	UARTA Mode = SBP
	SBP Message Mask = 64
	Configure Telemetry Radio On Boot = true
	Baud Rate = 57600, with 915 MHz radio
	UARTB Mode = NMEA
	SBP Message Mask = 0
	Configure Telemetry Radio On Boot = false
	Baud Rate = 9600, for NMEA standard
	GPGSY Msg Rate = 0
	GPRMC Msg Rate = 0
	GPVTG Msg Rate = 0
	GPGLL Msg Rate = 0
- With these settings, the 2 Piksis can communicate with each other and show the exact location of the rover
- For a more precise reading, program the base station with the exact coordinates where it is located
- The Base and the Rover Piksi both need at least 5 satellites for the location to work
- For an accurate reading, both the base station and the rover can't be indoors
- The satellite antenna can't be set on the ground, otherwise the Piksi won't read any satellites
- The higher up the antenna is, the better, and it can't be obstructed by anything

- The first test was hooking up the base station to a battery and connecting the rover to the computer

- The second test was hooking up the base station to the computer and connecting the rover to the battery
- With this configuration, I was able to get a Floating RTK reading on the Piksi Console, and it kept track of the rover's location
- However, the console does remove data from the screen after a set amount of time
- I need to look into the console and see if there is a record function that I can take advantage of
- With the above settings, the results show that the base station can read the rover's location, and the rover module can be set to send data to a slave/master configuration
- The data can be seen in the Baseline Tab on the Piksi Console
- Hardware works well enough to move on; now I need to work on the software to make it all work together
- The rover, when UARTB is set to NMEA, sends GPGGA data every 100 mS, in 80 mS bursts, sending <= 82 bytes of data
- This Data includes:
 	handshake, 			$
 	type of data, 			GPGGA
	UTC, 				hhmmss.sss (HrMinSec.mS)
	n/s data, 			ddmm.mmm (2 degrees and decimal minutes)
	n/s indicator, 			N or S
	e/w data, 			dddmm.mmmm (3 degrees and decimal minutes)
	e/w indicator, 			E or W
	position fix indicator, 	1=Fixed, 2=Differential, 3=Estimated, 4=Simulation
	# satellites, 			the number of satellites used
	HDOP,				The Horizontal Dilution of Precision(low is better)
	MSL Altitude, 			Units above Sea Level
	MSL units, 			M=Meters, F=Feet
	Geoid Separation, 		Distance Between WGS84 ellipsoid and geoid
	Geoid Units, 			M=Meters, F=Feet
	DGPS age, 			0000(time since last DGPS update)
	DGPS ref,	 		Reference station ID(blank if none)
	checksum, 			2-digit hex value
	and the stop bits, 		CL/LF
- We might only use the longitude, latitude, and maybe altitude; the rest is used to describe how accurate the data is
- The rover has the other NMEA data rates removed; this makes it so that the data it sends has no corruption or weird overwrites
- I haven't found a way to disable this yet; I might disable the other for now to get it working, and let a future student fix the problem
- The Piksi is hard-coded to 10Hz data transmission; there isn't a way to adjust this from the console 
- To fix this for the slave, I will have to program the slave so that it only stores and sends out data whenever the master calls for it
- I can either have the slave store the data once a second, and only send out the data when the transmission is complete, and the master calls for it; or I can program the slave so that it ignores the UART transmission until the master calls for it, in which case I can clock stretch the bus until it stores the needed data, then send out the required information
